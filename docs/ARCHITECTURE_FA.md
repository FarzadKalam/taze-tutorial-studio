# معماری تولید آموزش

عامل هماهنگ‌کننده در محیط Codex کاربر اجرا می‌شود. ابزار CLI خودش مدل یا agent جدید راه نمی‌اندازد. نقش‌های پژوهشگر، نویسنده، کارگردان ضبط و بازبین قرارداد کاری‌اند؛ برای شروع یک عامل کافی است. اجرای چند عامل مستقل در آینده می‌تواند با همین artifactها انجام شود.

## انتخاب محیط

اول محیط فعلی Codex بررسی می‌شود: مرورگر headless، سورس محصول، FFmpeg و امکان نوشتن خروجی. در محیط ابری ابزار همان‌جا نصب و اجرا می‌شود. وقتی Codex روی کامپیوتر شخص اجرا شده باشد، ابزار به محیط ابری ناموجود دسترسی پیدا نمی‌کند. `preflight` نوع محیط و شواهد آمادگی را ثبت می‌کند؛ تشخیص خودکار بهترین تلاش است، نه تضمین سرویس cloud.

مرورگر headless صفحهٔ محصول را در یک پروفایل تازه اجرا می‌کند؛ مانیتور، دسکتاپ و مرورگر شخصی ضبط نمی‌شوند. fallback محلی انتقال یک job است، نه اتصال مخفی از cloud به دستگاه کاربر.

## تکرار و بازیابی

هر برداشت در پوشهٔ تازه ساخته می‌شود و برداشت قبلی بازنویسی نمی‌شود. شکست مرحله `status.json` و تصویر شکست دارد. صدای هر گام بعد از موفقیت ذخیره می‌شود؛ گام‌های موفق بعد از شکست سرویس دوباره صورتحساب نمی‌شوند. تغییر متن یا تنظیمات صدا اثرانگشت کش را عوض می‌کند. `next` برای ادامه راهنمایی می‌دهد؛ فایل بازبینی جای اثبات خودکار کیفیت نیست.

سناریوها و ابزارها به Git می‌روند، session و خروجی‌ها نمی‌روند. handoff فقط قرارداد و سناریو است؛ رسانهٔ مجاز و checkout محصول برای ادامهٔ دقیق در محیط دیگر جدا منتقل می‌شوند. فعلاً handoff یک انتقال خودکار به سرویس cloud نیست.

## استقلال از پروژه‌ها

این ریپو به kalam-video-kit وابسته نیست؛ موتور و ابزارهای خودش را نسخه‌دار نصب می‌کند. برای فیلم‌برداری UI واقعی از checkout تازه‌سیستم به‌صورت فقط‌خواندنی import می‌شود. نبود سورس باید صریحاً گزارش شود. تولید ویدیو به تغییر یا deploy Kalamapp نیاز ندارد.

آموزش عمومی محصول متعلق به لایهٔ SaaS است. حساب تولیدکننده و مصرف صدا نباید از سازمان مشتری برداشته شود. اگر ابزار روزی به مشتریان فروخته شود، job، رسانه، اعتبار و دسترسی همگی باید per-org شوند؛ وضعیت فعلی یک ابزار داخلی است، نه سرویس multi-tenant آمادهٔ فروش.
