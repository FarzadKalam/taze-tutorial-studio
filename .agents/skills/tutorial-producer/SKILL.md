# تولید آموزش محصول

این ریپو موتورهای قابل تکرار دارد؛ تو عامل هماهنگ‌کننده و نویسنده‌ای. برای شروع README و AGENTS.md ریشه را بخوان. کلید API دیگری برای تصمیم‌گیری خودت لازم نیست؛ از همین نشست عامل استفاده کن. درخواست آزاد را صرفاً با جایگزینی نام یک سناریوی ثابت پاسخ نده.

## محیط اجرا

ابتدا `npm run preflight`. اولویت با محیط فعلی اجرای Codex است، چه sandbox ابری چه container. مرورگر headless فقط پنجرهٔ جداگانهٔ آموزشی را ضبط می‌کند؛ ضبط دسکتاپ شخص یا پروفایل شخصی Chrome نیست. در شکست ابزار، علت و فایل انتقال کار را ثبت کن. اگر اجرا روی cloud در دسترس نیست، آن را ادعا نکن. نصب وابستگی‌ها در همان محیط را امتحان کن؛ سپس در صورت لزوم پروژهٔ قابل‌ادامه برای محیط محلی بده. برای راه‌اندازی محیط، `scripts/setup.mjs` موجود است.

## قرارداد مراحل عامل

1. **بررسی محصول:** تاریخچه و تغییر محلی فایل‌های مرتبط را بررسی کن؛ مسیر واقعی و پیش‌نیازها را با منبع در `tutorials/<id>.json` ثبت کن. اصل سورس محصول را برای ضبط تغییر نده. موضوع یا دسترسی مبهم را فقط وقتی از کد قابل کشف نیست بپرس.

برای مرحلهٔ بیرون از محصول، بررسی کن آیا بخشی از یادگیری است؛ گرفتن توکن، ارسال پیام یا بررسی دریافت را بی‌توضیح حذف نکن. در `external-apps/<app>.json` مسیر، منبع رسمی، وضعیت تأیید و حالت‌های تصویر را ثبت کن. قاب گوشی reusable است؛ scene با `surface: {kind: "phone", app: "...", state: "..."}` انتخاب می‌شود. بازسازی همیشه برچسب دارد و متن خلاصه را نقل‌قول دقیق از برنامه معرفی نمی‌کند. در نبود شاهد برای نام یک دکمه، نام قطعی جعل نکن؛ راهنمای توضیحی بساز یا همان جزئیات را برای بررسی نگه دار.
2. **سناریو و تأیید اجباری مالک:** متن نهایی مبنا، نریشن دقیق، متن روی تصویر و سناریوی نمایش هر صحنه را با `npm run review -- <id>` بساز و به کاربر نمایش بده. لحن عملی، عامیانه، روشن و فارسی رایج ایران باشد؛ اصطلاح را در اولین کاربرد توضیح بده. تا تأیید صریح همین نسخه دریافت نشده هیچ صدا، ضبط، تدوین محتوایی یا رندر نهایی اجرا نکن. موافقت کلی با ساخت ابزار یا ورود به حساب، تأیید متن نیست. بعد از تأیید واقعی کاربر، اثرانگشت نسخه و مرجع پیام او را با `npm run approve -- <id> --hash <review-hash> --reference <actual-user-message>` ثبت کن. هر تغییر متن، سناریو یا هویت بصری تأیید تازه لازم دارد. بخش خارج از مرورگر را مشخص کن؛ نتیجهٔ ساختگی را واقعی نشان نده.
3. **صدا:** سرویس انتخاب‌شدهٔ صاحب کار؛ این پروژه از `generate_voice_output` تازه‌سیستم استفاده می‌کند. `npm run voice -- <id>` هر گام را جدا ذخیره می‌کند. خطای سرویس پولی را خودکار بی‌نهایت تکرار نکن. مدل نهایی واقعی را از پاسخ ثبت کن؛ درخواست Gemini تضمین دسترسی به آن نیست.
4. **ضبط:** `npm run capture -- <id>`، پیش‌فرض fixture با UI واقعی و دادهٔ ساختگی است. شکست assertion یعنی توقف همان برداشت؛ به گام بعد نرو. برای ضبط اتصال واقعی، حساب آموزشی و اعتبار همان کار باید مشخص باشد.
5. **تدوین:** `npm run compose -- <id>`؛ پروفایل `editing/product-tutorial.json` مبنای سلیقهٔ استخراج‌شده از video-kit است؛ اگر کیت در دسترس است توضیحات مرتبط تازهٔ مالک را هم بررسی کن، اما وجود کیت وابستگی اجرای این ریپو نیست. بافت آموزشی را حفظ کن: زوم این/اوت برای خواندن و حفظ مسیر، رد کوتاه ماوس و حلقهٔ کلیک با زمان واقعی، و نشان لمس در گوشی. HyperFrames پروژهٔ مستقل با فونت و رسانهٔ محلی می‌سازد. راهنمای موتور همان نسخه از مستندات رسمی/مهارت در دسترس را بخوان؛ رندر نباید به network وابسته باشد.
6. **بازبین:** قاب‌های واقعی، نام کنترل‌ها، فارسی، پوشاندن اطلاعات حساس، همگامی صوت و زمان و ffprobe را بررسی کن. `REVIEW.md` پروژه را با passed/failed/pending و شواهد بنویس. بررسی فنی را شنیدن واقعی معرفی نکن. `npm run next -- <id>` وضعیت قابل‌محاسبهٔ مراحل را نشان می‌دهد.
7. **انتشار:** بستهٔ `cms-draft.json` فقط پیش‌نویس محلی است. انتشار تنها پس از تکمیل بازبینی و در محدودهٔ درخواست کاربر؛ deploy frontend یا migration خودکار لازم نیست. پس از انتشار، صفحه و فایل واقعی را بررسی و مرجع SEO محصول را طبق قواعدش به‌روز کن.

## ادامه و تحویل

در شروع مجدد `npm run next -- <id>` را بخوان، ورودی‌های تغییرکرده را بررسی و فقط مراحل لازم را بازتولید کن. پروندهٔ کار در `.local/projects/<id>` و سناریو در `tutorials` است؛ کلید و نشست نباید وارد فایل انتقال شوند. `npm run handoff -- <id>` بستهٔ انتقال بدون صدا/تصویر خصوصی یا credential می‌سازد. برای انتقال رسانه‌ها، فایل‌های محلیِ مشخص و مجاز را جدا منتقل کن.

یک عامل با نقش‌های بالا برای شروع کافی است؛ نقش را با فراخوانی چند مدل یا ادعای اجرای چند عامل برابر ندان. موازی‌سازی فقط برای بررسی‌های مستقل و در صورت وجود اختیار و ابزار؛ تصمیم نهایی و پروندهٔ کار یک مالک دارند.
